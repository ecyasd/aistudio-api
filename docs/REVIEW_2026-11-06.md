## 两套实现的选择

| 维度 | 当前 fork | AIS2 固定版本 | 选择 |
| --- | --- | --- | --- |
| 服务主体 | Python / FastAPI，复用上游 WAA signer 和 HTTP 网关 | Go，配套账户与 WAA 运行时 | 保留现有主体，避免重做已验证的生成链路 |
| 默认 WAA | 当前 browserless 引擎；可选 CloakBrowser | SpiderMonkey；可选 Camoufox | 两者都有无浏览器路线，不能以“只有 AIS2 会常驻浏览器”解释差异 |
| 对外协议 | Gemini 原生、OpenAI Chat Completions，服务酒馆场景 | 额外覆盖 Responses、Anthropic 等入口 | 维持当前产品范围，不为导入功能整体换后端 |
| 上游通道 | PG 与 `-build` 写代码助手共享账户基础，按完整模型 ID 区分状态 | PG、Build 写代码助手及其配套调度 | 保持当前通道、请求上下文和取消行为 |
| Cookie 解析 | 原有多格式入口，但前后端重复投影、结构化 bundle 处理不一致 | 统一解析 StorageState，校验域、路径、期限和关键凭据 | 将格式和元数据归一化集中到后端 |
| 身份发现 | 原有循环没有硬上限，400/403 也被当作身份存在 | 最多 10 个身份、重复邮箱停止，先发现再选择 | 本轮补上硬上限和独立身份依据，保留默认离线保存 |
| 环境信息 | 使用当前服务引擎配置 | CDP 读取语言/时区；配套运行时消费账户固定指纹 | 导入兼容字段并说明边界，不把无法消费的指纹写入假装生效 |
| 会话续签 | 普通 Cookie 生命周期 | 部分 Chrome OAuth 或远程配对来源具备额外续签能力 | 不把保存 OAuth 字段等同于实现续签 |

这组改动没有新增常驻浏览器或后台身份探测任务。实际资源占用和可承载账户数需要在目标环境测量，本次未给出性能数字。

## Cookie 导入支持与限制

支持 Cookie 请求头、多行键值、Cookie-Editor 数组、键值对象、`cookies` / `cookie` 包装、Playwright / AIS2 storage state、Netscape 文件、`accounts` / `profiles` 账号包和包含 `storage_state` / `storageState` 的单账号配对对象。每个来源最多 2 MiB，每个包最多 100 个账号。

签名校验遵循本项目已有的 SAPISID → `__Secure-3PAPISID` → APISID 回退，不照搬 AIS2 的四项 Cookie 硬门槛。保存成功只表示格式及本地必需字段通过，不能证明登录仍有效或账号具备上游模型权限。

Cookie 运行时仍采用现有扁平凭据字典，本轮只保存支持的 Google 认证 Cookie，先在导入时限制作用域和检查有效期。没有把它改造成完整浏览器 Cookie jar；也没有把原浏览器 OAuth、localStorage、指纹配置或设备绑定状态迁移进当前运行时。

默认界面导入传 `probe_identity=false`，不会触发 Google 探测。旧 API 客户端省略此字段仍沿用原有探测默认值。选择识别多个身份时会显式联网，但本次测试没有执行该真实动作。

全包预检保证格式、凭据和目标路径校验错误发生在首次保存之前；多个账号的磁盘写入不是数据库事务，系统断电或写盘失败仍可能留下已保存的部分。本轮使每个成功保存的当前账号及时刷新会话，没有宣称实现跨文件原子事务。

## 为什么指纹浏览器导入不用手填时区

AIS2 的 [CDP 导入代码](https://github.com/Mag1cFall/AIStudio2API/blob/80847a7665c442a238918c957963217773f36291/internal/chromeauth/cdp.go) 会额外读取浏览器的 `navigator.language` 和 `Intl.DateTimeFormat().resolvedOptions().timeZone`。它读取的并非 Cookie 自带的时区，也没有因此复制原 Chromium 的全部指纹。

完整配对对象由 [pairing.go](https://github.com/Mag1cFall/AIStudio2API/blob/80847a7665c442a238918c957963217773f36291/internal/api/pairing.go) 定义，形状为 `{label, locale, timezone, auth_user, storage_state, fingerprint}`；账户通常分开保存 `account.json`、`storage-state.json` 与 `camoufox-fingerprint.json`。未找到所谓原生 `[storageState, fingerprint]` 二元数组协议。

AIS2 的 [Camoufox 指纹管理](https://github.com/Mag1cFall/AIStudio2API/blob/80847a7665c442a238918c957963217773f36291/internal/camoufoxnative/fingerprint.go) 与 [SpiderMonkey runtime](https://github.com/Mag1cFall/AIStudio2API/blob/80847a7665c442a238918c957963217773f36291/internal/aistudio/runtime_go.go) 会消费其配套账户指纹。本项目的 CloakBrowser 和 WAA signer 配置链不同，因此界面明确提示“仅导入兼容 Cookie 与账号信息，来源浏览器环境未应用”。

## 后续优先级

1. 如要达到 AIS2 的完整导入体验，下一步是“发现身份 → 预览邮箱和现有账号 → 勾选保存”的独立流程；当前仍是可选的识别并导入，未新增后台任务队列。
2. 每账号时区、语言和指纹只有在 WAA 与 HTTP 请求两端共同消费时才有意义，应独立设计和验证。CDP 接入、Windows Chrome OAuth、原设备续签和远程配对不属于简单文件兼容。
3. `routes_system.py` 的签名服务器诊断仍有管理端原始异常文本，本轮未扩大到该诊断接口。可在后续统一为结构化、脱敏的诊断结果。
4. 构建继续提示 UsageView 图表包超过 500 kB。这不阻断本轮构建；若有首屏性能证据，再按 ECharts 使用范围收窄导入和拆包。本轮不为消除告警改变图表行为。
